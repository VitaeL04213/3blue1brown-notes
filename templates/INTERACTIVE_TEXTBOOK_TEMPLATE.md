# 交互式数学教材创作模板

> 用途：把系列课程重构成能够连续阅读、动手探索、核对推导的教材，同时产出网页、LaTeX/PDF 与适当范围的 Lean 证明。
>
> 使用方法：先填写项目设定，再为每章、每节复制相应模板。所有 `{{字段}}` 均需替换。示例用于说明写法；本文件本身不参与教材构建。
>
> 本模板提炼自 3Blue1Brown 中文导学教材。复用于其他课程时，保留教学流程，根据主题重新选择例子、模型与证明范围；附录中的路径是本仓库的具体实现。

## 2. 写作的基本方法

每节围绕一个值得回答的问题展开，使读者经历以下过程：

**具体问题 → 直观模型 → 可检验的预测 → 操作与观察 → 数学表述 → 推导或证明 → 应用与边界。**

正文以连贯论述承担解释任务。公式前说明为什么需要它，公式后解释每一项、成立条件以及它回答了什么问题。段落之间交代推理如何继续，避免把课程缩成概念清单和公式摘抄。

直观应服务于概念本身：

- 几何对象可通过位移、投影、面积、方向与维数解释。
- 变化和累积可通过速度、流量、存量及单位解释。
- 概率与学习可通过信息读取、误差、编码代价及反馈解释。
- 抽象代数可通过运算规则和具体模型解释，无须强行添加物理故事。

参考教材的组织形式，用自己的例子与论述重建内容。定义负责明确对象，命题负责陈述结论，证明负责解释结论为何成立；动画与数值实验帮助发现和检查现象。

## 3. 从目录到完整教材的工作流程

| 阶段 | 要做的工作 | 可检查的产物 |
|---|---|---|
| 确定范围 | 核实官方目录、去重、记录来源，建立先修关系与术语表 | 课程清单、来源记录、全书目录 |
| 建立样章 | 先完成一节的正文、实验、证明、网页和 PDF，确定阅读体验 | 一节可实际阅读与操作的样章 |
| 编写章节 | 用同一教学框架逐节独立写作，按概念选例子和演示 | 章节导言、逐课正文、算例与习题 |
| 连接图文 | 为每个讲解步骤配置可重复的状态，核对文字与图形 | 步骤表、模型、预设和实时读数 |
| 精确化结论 | 写出假设、证明和边界，选取适合的命题进行 Lean 形式化 | 命题、纸笔证明、Lean 文件与范围说明 |
| 生成多种版本 | 从共同内容生成网页和 PDF，保留媒体入口 | 可阅读网页、可搜索 PDF、可复现源码 |
| 检查与修订 | 检查数学、交互、排版、引用、中文提取和编号 | 真实执行的验证记录与修订结果 |
| 发布 | 提交源码与产物，检查构建和线上内容 | 仓库链接、在线教材、PDF、提交标识 |

先把样章做完整，再扩展到全书。批量生成适合处理目录、编号和页面外壳；具体解释、例子和教学步骤仍需逐节判断。

## 6. 写法示例：由网格剪切理解矩阵

下面展示一段完整的推理写法。替换课程时，应重写问题和机制，而非只替换术语。

### 先确定我们在改变什么

把平面上的箭头看作一次位移。固定矩阵后，拖动输入箭头是在改变送入规则的对象；修改矩阵的一列，则是在改变规则本身。先用恒等变换核对两幅图：输入的坐标是什么，输出就是什么。只有分清这两种操作，之后的图形变化才有明确含义。

### 两根基向量怎样决定整个网格

现在保持第一根基向量不动，把第二根基向量的终点移到 $(1,1)$。在动手前先预测：输入 $(1,2)$ 将去哪里？它原本是一份第一基向量加上两份第二基向量。线性映射保持这个组合，因此输出为 $(1,0)+2(1,1)=(3,2)$。对一般输入重复这个推理，就得到 $(x,y)\mapsto(x+y,y)$，对应矩阵

$$
A=\begin{pmatrix}1&1\\0&1\end{pmatrix}.
$$

公式中的两列记录基向量的去向。它们使我们能够计算任意输入的输出，也解释了为什么一整张网格会按同一规则倾斜。

### 用压扁检查“线性”和“可逆”的区别

把两列改成 $(1,1)$ 与 $(2,2)$。输出成为 $(x+2y,x+2y)$，只落在一条直线上；两个不同输入 $(2,0)$ 和 $(0,1)$ 都得到 $(2,2)$。这个变换仍保持相加和数乘，所以仍然线性，但已不能从输出唯一恢复输入。图像提示了差别，具体的两个原像则给出了不可逆的证据。

**此例的教学检查：** 读者应能够解释列的含义、手算一个输出，并区分线性与可逆；图中应同时提供输入、两列、输出与行列式读数。

## 8. 页面与媒体组织

### 阅读布局

宽屏采用“目录—正文—实验”的组织方式。正文与实验共同使用页面可用宽度，实验位于右侧，随阅读保持可见。左文中的按钮与右图中的状态提示对应，读者可以在解释和操作之间反复核对。

屏幕变窄后改为上下排列，保留从步骤到实验、再返回当前步骤的入口。长公式在局部滚动，不把整页撑出屏幕。例题、解答、证明可按需展开，打印时展开应阅读的内容。

### 媒体使用表

| 类型 | 适合的用途 | 必须提供的信息 |
|---|---|---|
| 官方原视频 | 回看原课程的动态解释 | 作者、原链接、观课问题；按需加载播放器 |
| 原课图示 | 对照原作者的图形表达 | 出处、署名及可用许可；无法确认复用条件时提供官方图文入口 |
| 原创 Manim 动画 | 展示一个预设情形的连续演化 | 场景源码、播放文件、关键帧、文字解释 |
| 实时交互图 | 改变参数、拖动对象、观察即时反馈 | 数学模型、操作说明、数值读数、边界处理 |
| PDF 静态插图 | 辅助打印和连续阅读 | 图注、关键关系，以及对应网页实验链接 |

逐张说明图形代表什么、应观察什么，以及它与当前推导的关系。原视频、预渲染动画、可交互图分别标明，避免让读者误以为一个固定动画可以任意调参。

## 9. LaTeX、网页与 Lean 如何共同维护

正文、逐步讲解、定义和证明应有明确的共同来源。网页负责导航与交互，PDF 负责连续阅读与打印；修改同一个概念时，从共同来源更新两种输出。

Lean 命题应先根据纸笔陈述明确类型与假设，再实现证明。一般定理、具体特例和局部恒等式应分别说明覆盖范围。形式证明、数值测试与图形观察各自回答不同的问题，验证记录须指出实际完成的是哪一种。

### 本仓库的复现命令

在仓库根目录执行；先按 README 配好 Python、Node、Lean 与 LaTeX 环境。以下列出完整流程，日常修改按影响范围选择检查。

~~~sh
python -m pip install -r requirements-authoring.txt
python scripts/build_site.py
node scripts/check_models.cjs
python scripts/check_textbook.py

python -m playwright install chromium
python scripts/check_browser.py

python scripts/build_pdf.py
python scripts/check_pdf_text.py
python scripts/review_pdf.py

lake build
python scripts/audit.py
lake env lean scripts/AxiomAudit.lean
~~~

`review_pdf.py` 需要 Poppler 的 `pdftoppm`，生成的页面图与联系表仍需视觉检查。编译器不在 PATH 时，向 `build_pdf.py` 传入 `--tectonic` 和实际路径。首次配置 Lean/mathlib 可按 README 获取缓存；固定版本以项目配置为准。

仅修改说明文档时检查文字、链接与差异即可。改动数学模型时检查关键数值与边界；改动排版或交互时检查实际页面；改动共享正文时同步生成网页和 PDF；改动形式命题时运行 Lean。记录实际执行的检查，不把计划中的项目写成“已通过”。
